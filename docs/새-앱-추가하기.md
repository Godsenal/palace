# 새 앱을 palace에 추가하기

palace는 **매니페스트 한 장**으로 앱을 늘린다. 새 도구를 만들었을 때 거치는 전체 과정.

---

## 1. 도구를 평소처럼 만든다

palace가 강제하는 특별한 규약은 거의 없다. 다만 palace가 잘 다루려면 아래를 갖추면 좋다
(전부 필수는 아님):

| 요소 | 왜 필요한가 | 예 |
|---|---|---|
| **GitHub repo** | 설치(clone)·업데이트(pull) | `Godsenal/my-tool` |
| **설치 명령** | clone 후 1회 셋업 | `bun install`, `npm ci`, `./install.sh` |
| **시작 명령** | 실행 | `bun start`, `loopctl dashboard`, `npm run dev` |
| **로컬 대시보드**(선택) | 실행 감지 + `<webview>` 임베드 | `http://localhost:3000` + 포트 `3000` |
| **README.md** | 문서 탭 | 표준 README |
| **전제 도구**(선택) | 진단·자동설치 | `bun`, `gh`, `cmux` … |

> 대시보드가 있으면 palace가 그 **포트가 열렸는지**로 "실행 중"을 판정하고, 열리면 창 안에 그대로 임베드한다.
> 없으면 실행 상태는 palace가 직접 띄운 프로세스(process 모드)일 때만 알 수 있다.

## 2. 기동 방식(launchMode)을 정한다

| 값 | 언제 | palace 동작 |
|---|---|---|
| `process` | 독립 프로세스로 돌아도 되는 것 | palace가 자식 프로세스로 spawn, 로그/정지 관리 |
| `cmux` | **cmux 아래에서 돌아야 하는 것**(cmuxOnly, cmux 패널 전제) | `cmux new-workspace --cwd … --command …` 로 위임 |
| `manual` | 사람이 직접 켜야 하는 것 | 명령만 안내 |

`cmux-remote`·`loops`는 cmux 전제라 `cmux`. 대부분의 순수 서버/CLI는 `process`.

## 3. palace에 등록한다 — 두 갈래

### A. UI로 (그 머신에만, 즉시)

좌하단 **＋ 앱 추가** → repo URL·설치/시작 명령·대시보드 URL 입력 → `~/.palace/apps/<id>.json` 생성.
가장 빠르다. 그 컴퓨터에서만 보인다.

### B. 매니페스트 파일로 (그 머신에만, 즉시)

같은 JSON을 직접 써서 `~/.palace/apps/<id>.json`에 떨군다. 세밀한 필드(전제 도구, 감지 경로,
추가 문서)까지 지정할 때. 전체 스키마:

```jsonc
{
  "id": "my-tool",                       // 고유 id (= 폴더명)
  "name": "my-tool",
  "tagline": "한 줄 소개",
  "description": "길게 설명(선택)",
  "repo": "git@github.com:Godsenal/my-tool.git",
  "repoHttps": "https://github.com/Godsenal/my-tool",
  "runtime": "bun",                      // bun | node | other
  "accent": "#7c9cff",                   // 사이드바 강조색(선택)

  "detectPaths": ["~/LTH/my-tool"],      // 이미 clone돼 있으면 재clone 없이 감지
  "launchMode": "process",               // process | cmux | manual

  "prerequisites": [                     // 진단/자동설치 대상
    { "name": "bun", "check": "bun --version",
      "install": "curl -fsSL https://bun.sh/install | bash" },
    { "name": "Homebrew", "check": "command -v brew",
      "install": "…", "manual": true,    // manual=palace 자동설치 안 함(암호/GUI/로그인)
      "note": "관리자 암호 필요 — 터미널에서 직접" }
  ],

  "install": [{ "run": "bun install" }], // clone 후 1회
  "update":  [{ "run": "git pull --ff-only" }, { "run": "bun install" }],
  "start":   { "run": "bun start" },     // process면 spawn, cmux면 위임 명령
  "dashboard": { "url": "http://localhost:3000", "port": 3000 },
  "readme": "README.md",
  "extraDocs": ["CLAUDE.md"]             // 문서 탭 추가 파일(선택)
}
```

### C. 내장으로 (모든 머신 기본 제공, 재빌드 필요)

`src/shared/manifests.ts`의 `BUILTIN_MANIFESTS` 배열에 위 객체를 추가하고 `builtin: true` →
`npm run build`(개발) 또는 `npm run dist:mac`(패키징). palace를 새로 설치하는 **모든 컴퓨터**에서
기본 카탈로그로 뜬다. cmux-remote·loops가 이 방식.

> 정리: **나만 쓸 거면 A/B**(즉시, 재빌드 X) · **palace 배포본에 기본 탑재할 거면 C**(재빌드).

## 4. 끝 — 카탈로그에 뜬다

등록되면 palace가 나머지를 한다: 전제 진단·자동설치 → 설치(clone+스텝) → 시작 → 대시보드 임베드 →
업데이트 → README 문서. 앞으로 도구를 몇 개를 더 만들든 이 4단계를 반복하면 된다.

---

### 체크리스트

- [ ] 도구 repo가 GitHub에 있다 (clone 가능)
- [ ] 설치·시작 명령이 정해졌다
- [ ] (있다면) 대시보드 URL·포트를 안다
- [ ] launchMode를 정했다 (cmux 전제인가?)
- [ ] 전제 도구의 check/install 명령을 적었다
- [ ] A/B(나만) 또는 C(배포 기본)로 등록했다
