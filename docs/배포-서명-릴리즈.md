# 배포 · 서명 · 자동업데이트

palace를 새 버전으로 내보내는 전체 흐름과, 서명/공증을 켜는 법.

## 릴리즈 컷 (태그 하나로)

```sh
# 1) 버전 올리기
npm version patch      # package.json 0.1.0 → 0.1.1 + 커밋 + 태그 v0.1.1
git push && git push --tags
```

`v*` 태그가 push되면 **GitHub Actions `release` 워크플로우**가:
1. macOS 러너에서 `npm ci && npm run release`
2. electron-builder가 `.dmg` / `.zip` / `latest-mac.yml` 생성
3. **GitHub Releases에 게시**

그러면 이미 palace를 쓰는 컴퓨터들은 시작할 때 `electron-updater`가 그 릴리즈를 보고 **자동 갱신**한다
(설정 ⚙️ → "업데이트 확인"으로 수동 확인도 가능).

> ⚠️ **macOS 무음 자동적용은 서명이 있어야** 동작한다. 서명 전에는 "새 버전 있음" 확인/알림 + 다운로드까지만 되고,
> 실제 교체는 사용자가 새 `.dmg`를 받아야 한다. 아래 서명을 켜면 완전 자동이 된다.

## 서명 + 공증 켜기 (한 번만 셋업)

필요한 것: **Apple Developer Program**(연 $99) + **Developer ID Application** 인증서.

1. Xcode/개발자 사이트에서 **Developer ID Application** 인증서를 만들고 키체인에서 `.p12`로 내보낸다.
2. base64로 인코딩:
   ```sh
   base64 -i DeveloperID.p12 | pbcopy
   ```
3. GitHub 저장소 **Settings → Secrets and variables → Actions**에 등록:
   | 시크릿 | 값 |
   |---|---|
   | `CSC_LINK` | 위 base64 문자열 |
   | `CSC_KEY_PASSWORD` | `.p12` 비밀번호 |
   | `APPLE_ID` | Apple 계정 이메일 |
   | `APPLE_APP_SPECIFIC_PASSWORD` | appleid.apple.com에서 만든 앱 암호 |
   | `APPLE_TEAM_ID` | 개발자 팀 ID (10자) |
4. 끝. 다음 `v*` 태그부터 CI가 **자동으로 서명 + 공증**해서 게시한다.
   (`electron-builder.config.cjs`가 `CSC_LINK` 존재를 감지해 서명 경로로 전환)

### 로컬에서 서명 빌드하고 싶으면
```sh
CSC_LINK=... CSC_KEY_PASSWORD=... APPLE_TEAM_ID=... APPLE_ID=... APPLE_APP_SPECIFIC_PASSWORD=... \
  npm run dist:mac
# 또는 인증서가 키체인에 있으면: PALACE_SIGN=1 npm run dist:mac
```

## 서명 전 임시 배포

unsigned `.dmg`를 받은 사람은 Gatekeeper가 막을 수 있다. 우회:
- **우클릭 → 열기** 한 번, 또는
- `xattr -dr com.apple.quarantine /Applications/palace.app`

로컬에서 직접 빌드해 쓰는 경우(당신)는 quarantine이 안 붙어 그냥 열린다.

## CI 점검(`ci` 워크플로우)

main에 push하거나 PR을 열면 `typecheck` + `build`가 자동으로 돈다. 릴리즈 전에 깨진 걸 먼저 잡는다.
